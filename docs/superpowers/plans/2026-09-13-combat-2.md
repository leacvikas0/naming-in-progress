# Combat 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the wave brawler into a duo-party action roguelite: two heroes, elemental auras and reactions, heavy/super/perfect-dodge verbs, momentum, readable enemy choreography, and a living arena.

**Architecture:** Every module keeps the frozen contract: no game module imports another; `main.js` is the only wirer; everything else talks over `events.js`. The party is a model swap plus per-hero stat sheets — all four heroes are KayKit on one skeleton, so no re-rigging. Auras and reactions are enemy-side state; the attack payload carries the attacker's multipliers so `enemies.js` can resolve everything it needs without reaching back into `player.js`.

**Tech Stack:** Vanilla ES modules, three.js 0.170 (CDN import map), node test runner (plain `node file.mjs`), DOM HUD, hand-authored pixel chrome.

**Spec:** `docs/superpowers/specs/2026-09-13-combat-2-design.md` — read it first. It is the contract; this plan is the task order.

## Global Constraints

- Do NOT change `game/src/CONTRACT.md` module boundaries. Modules may import `three`, `./events.js`, `./balance.js` only. `main.js` wires.
- Do NOT add new game modules beyond those in this plan. `reactions` and `momentum` live in `balance.js` as pure helpers.
- All existing 47 tests must stay green.
- New tests are plain node scripts: no framework, `strict as assert`, a local `test(name, fn)` counter, `process.exitCode = 1` on failure, `console.log("  ok  ...")`. Copy the pattern from `game/tests/balance.test.mjs`.
- Work only inside `.worktrees/combat-2`. Do not commit from a subagent; leave changes staged-free for the orchestrator to commit.
- Every new tunable goes in `balance.js` `CONFIG` or the relevant data table. No magic numbers in module bodies.
- Element ids are exactly: `frost`, `ember`, `shadow`, `arcane`. Reaction ids exactly: `melt`, `overload`, `shatter`, `detonate`, `frozen`, `void`.
- Keep `game/tests/ui.test.mjs` green: any new chrome asset must be registered in `game/ui/build-ui.mjs` and the REQUIRED list of that test.

### Task B: player party, swap, momentum, heavy, super, perfect dodge

**Files:**
- Modify: `game/src/player.js`
- Create: `game/tests/party.test.mjs`

**Interfaces consumed:** Task A's `ELEMENTS`, `MOMENTUM_GAIN`, `momentumAfter`, `CONFIG.player.momentumMax`.
**Interfaces produced:** `createPlayer({ ..., hero, partner })`; returned object gains `swap()`, `activeHero`, `party`, `momentum`, `superReady`, `swapCooldownFrac`. `input` gains `{ heavy, super, swap }`. `player-attack` payload gains `{ element, kind, stun, knockback, reactionMult, executeMult, reactionHeal, auraMult }`. Emits `swap { from, to, element, color }`, `momentum { value, max, ready }`, `super-used { hero, position }`.

**Resolved details:**
- **Perfect dodge is resolved by the player, not the enemy.** In `damage()`, if `dodgeIFramesT > 0` the hit is already negated — that negation is the perfect dodge: emit `perfect-dodge { position }` there (enemies.js only forwards the same event when it skips its own damage call; guard against double-emit with a 0.25s internal cooldown). Effect: +25 momentum, 3s empowered window (`stats.perfectT`), emit `sfx` name `"dodge"` pitch 1.3.
- **Element sources**: light/heavy use `activeHero.element`; super uses the same. Payload carries `reactionMult` (stats), `executeMult` (stats), `auraMult` (stats).
- **Heavy**: `kind: "heavy"`, `stun` from hero.heavy.stun, `knockback` from hero.heavy.knockback; committed until impact then dodge-cancellable; consumes one momentum-free cooldown of 1.0s.
- **Super shapes** by `hero.super.id`: `nova` (360° hit + knockback + stun), `whirlwind` (0.35s tick, 3s duration, player keeps moving), `flurry` (blink to nearest 5, 4 hits each, 0.12s apart), `meteor` (0.8s delay then 5.0 radius blast at aim point). During the 1.2s entry the player is invulnerable and slowed to 0.25 timescale via `events.emit("hitstop", { duration: 0.35 })` plus `fx.slowmo` — player only emits `super-used`; fx owns the slowdown.

**Steps:**

- [ ] **Step 1: Failing test** `game/tests/party.test.mjs`: build a player with a fake scene/world/events (no loader — pass `loader: null` and hero with no `glb`), assert: swap() toggles activeHero and respects cooldown; party has 2 entries with independent hp; damage to active hero reduces only that hero's hp; when active hp hits 0 with partner alive the party auto-swaps and does not emit player-died; when both are 0 it emits player-died; momentumAfter integration clamps.
- [ ] **Step 2: Run, confirm fail.**
- [ ] **Step 3: Implement** per spec §Verbs and §Momentum: heavy attack state machine (committed, dodge-cancel after impact), super shapes (`nova`/`whirlwind`/`flurry`/`meteor`), perfect-dodge listener (+25 momentum, slowmo via `events.emit("slowmo")`? NO — fx owns slowmo; player emits `perfect-dodge`; fx listens), per-hero hp, swap with i-frames + `swapFx` event, stat bag gains `reactionMult, auraMult, momentumMult, swapCooldownMult, executeMult, reactionHeal`.
- [ ] **Step 4: Run** `node game/tests/party.test.mjs && npm test`.
- [ ] **Step 5: Report** exact API to orchestrator.
